A 股股东关系网络与时间线分析 validated

通过 9 个 spike 实验验证 · 2026-05-13 · 来自 /spike · 详细版见 agent 设计文档

这是什么

一个本地 Web 应用，把 A 股上市公司"前十大股东"季报数据系统化：能按人物看一个自然人在哪些公司持股、跨公司持仓比例 / 市值时间线、谁是他常见合伙人；能按公司看 N 年股权结构变迁；能挖掘家族 / 一致行动人；能关联 Wikidata 资料。最关键的是验证了 同名消歧算法 —— A 股股东重名严重（"吕强"在 111 家公司其实是几十个不同人），spike 中的拓扑算法能自动拆出来。

怎么工作的

核心难点不是"抓数据"（AKShare 已经把东财源包装得很好），而是同一个名字可能对应多个不同的真人 —— A 股股东披露只有"姓名"，没有身份证、出生年月，API 把所有同名股东合并返回。整个系统围绕"区分人 ≠ 区分名字"这件事来组织。

用一个真实案例展示 搜索"吕强"。东财说他在 111 家 公司有持仓 —— 看起来是个超级散户。但深入看：他和"香港中央结算"在 63 家公司"协同"（一个自然人不可能 63 家走港股通入仓）、"吕"姓里第二名"吕良丰"只有 12 家（断崖）—— 这"吕强"其实是几十个不同的真人被合并成了一条。

系统做的事：把"吕强"在 111 家公司的出现当成节点，两家公司只要共享 ≥ 1 个非平凡个人协同股东就连边，跑连通分量。结果拆成 92 个候选实体：
  • 高置信 「吕强」#1 · 13 家公司 · "与李红同公司 10 次" —— 几乎可以确定的真实"吕强 + 李红"家族 / 合伙关系
  • 中置信 「吕强」#2..#8 · 各 2 家 · 不同协同人
  • 单飞 ×84 这 84 家几乎肯定是 84 个不同的"吕强"，单凭拓扑信号无法关联
对照：搜索"王传福" → 只在比亚迪 1 家 → 不触发消歧 → 直接展示该人物的 19 个季度持仓时间线、Wikidata（Q716030、1966-04-08、比亚迪 CEO）、当前市值 1578 亿。

四个视图（永远从一个焦点出发）

三条铁律

  • 永远从一个具体焦点开始，不展示全市场（避免节点爆炸）
  • 网络图节点硬上限 ~100，超过自动折叠或强制过滤
  • 全市场聚合分析后端预聚合，前端只读快照（榜单 / 簇 / 异动）

关键决策 & 为什么

  • 数据源用 AKShare（不是 Tushare）：免费、覆盖好、`stock_gdfx_*` 系列字段稳定；Tushare Pro `top10_holders` 要 2000 积分门槛
  • 行情用腾讯源 `stock_zh_a_hist_tx`：AKShare 默认走东财 `push2his` 子域被 GFW 截断（TLS 握手后空响应）；腾讯源稳定
  • 市值同时存不复权 + 前复权：不复权用于"当时市值"，前复权用于"持仓真实变化趋势"
  • 不上 Tushare / Wind，因为受众是小团队 / 朋友圈，零预算；数据源选型按"免费 + 稳定"优先
  • 同名消歧不追求 100% 精确：采用"置信度分级 + 实体桶 + 人工修正"；置信度用文字标签 + 证据而不是百分比（避免"85%" 这种伪精确）
  • URL 层级 Hub/Entity 分离：#/p/吕强 是 hub 页（只有桶卡片）、#/p/吕强/1 是 entity 页；避免"既承认 N 人又把数据混着算"的自相矛盾
  • 前端 TS + React + Vite + TanStack Query/Table：不上 Next.js（不需 SSR）、不上 Tailwind（数据密集型 UI 自定义多）、不上 Redux（TanStack Query 够）
  • 本地 Web 服务而非桌面 app 或 Claude skill：可视化需求强、数据量大需本地 DB、团队多人用、deploy 链路最短
  • SQLite 而非 PostgreSQL：单机够用，5 个文件分库避免锁争用；> 100M 行时再考虑升级
  • 抓取调度按财报披露窗口加密：4 月底 / 8 月底 / 10 月底 / 次年 4 月底前后每天增量；其余时间每周一次扫盲

已验证（数据为证）

  • 数据链路通：美的 + 比亚迪 19 季度共 19 行 / 季度 × 2 公司 × 2 接口数据全部拉到，SQLite 存得下、查得快
  • 市值算对：王传福 (5.14 亿股 × 收盘价) 时间线：308 亿 (2020Q1) → 1713 亿 (2022Q2 高点) → 1017 亿 (2023Q4 低点) → 1578 亿 (2024Q3)，与公开报道一致
  • Wikidata 头部覆盖好：王传福 / 方洪波 / 吕向阳 / 夏佐全 全部命中，含结构化字段（出生年月、雇主、zh-wiki 链接、QID）
  • 协同分析数据是金矿：东财预聚合了 1434 个核心个人股东的跨公司持仓，37,620 个不重复股东 / 716,875 条协同关系
  • 家族 / 一致行动人识别准：陈海华+徐国新 30 家、周信钢+李欣 28 家、李东璘+魏巍 25 家 等都是稳定可识别的协同对
  • 同名消歧算法成功：吕强 111 家 → 92 桶，最大桶 13 家含李红 10 次 → 与"吕强+李红"协同对完全吻合；陈峰 56 家 → 42 桶（无大桶，正确识别多人）；王传福 1 家 → 1 桶（不误拆）
  • UI 四视图 + 主题切换 + 排序 + 分页可用：单文件 ~1300 行 v2 原型，浏览器内可玩

遗留问题与风险

  • Layer 3 软聚类未做：吕强 84 个单飞桶无法进一步关联或拆分；工程化阶段要补"行业 + 注册地 + 时间窗 + 持股顺位"软聚类
  • Layer 5 人工修正 UI 未做：用户合并 / 拆分 / 绑定 QID 操作 + audit trail 沉淀进 user_annotation 表反哺算法 —— 工程化重要补充
  • 协同分析"个股详情"截断：每条 record 只给前 10 家。"30 家协同"只知道其中 10 家具体名字
  • GFW 风险：东财 push2his 子域被截断已有 workaround（腾讯源）；未来其他子域也可能变化，需要监控
  • Wikidata 命中可能错绑：UI 上必须显示"可能对应该实体或别的同名实体"提示，避免给出虚假身份
  • 合规边际：数据公开披露 → 抓取本身合规；但整合后展示个人身份信息有边际风险；当前明确"小团队 / 朋友圈 + Caddy basic auth"使用，不部署到公网
  • 性能瓶颈：全市场全历史 20 年单线程抓取需 ~18 天，必须并发 + 增量；Day 0 拿最近一期可上线，历史回填后台跑
