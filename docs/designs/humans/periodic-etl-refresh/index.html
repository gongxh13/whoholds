这是什么

让数据每周自动刷新，完全不依赖任何人本机开机。 GitHub Actions runner 每周一晚上自动跑增量 ETL，重切 hot 分片，覆盖式上传到固定 Release tag。 朋友本地 cron 拉新 hot 就跟得上。

关键架构选择：GitHub Actions 是唯一 ETL 权威。 本机也走 snapshot pull 拿数据， 和朋友一样是消费者。这样消除了"我休假 → 朋友数据停更"的风险，也把流水线变得显式可观察。

决策与原因

  • 触发器选 GitHub Actions，不是本机 cron / launchd。launchd 关机就不跑；APScheduler 还要求 backend 跑着；GH Actions 完全云端，没有任何本机依赖。
  • 每周一次，不是每天。A 股财报披露不天天有；daily prices 7 天份一次拉齐就够；GH Actions free tier 配额也省。
  • 权威在 GH Actions，不是本机。代价是本机看数据也要先 snapshot pull，但消除"我关机一周数据停更"的脆弱性。
  • Release attachment 当数据持久层，不是 GH Actions cache。cache 5 GB / 7 天 evict 不可靠；Release 永久持有，且本来就是朋友拉数据的通道，复用一个。
  • 固定 release tag (data-snapshot) 覆盖式更新，不每周新建 tag。朋友 cron 命令永不变。

验证过什么

  • 海外出口可达：实测走 127.0.0.1:7897 境外代理拉 sh600004 最近 7 天 K 线，完整 7 行返回。push2his.eastmoney.com 海外可达，GH Actions Azure 出口同理可通。
  • 耗时可控：单股 daily prices 增量 ~1.07 秒（境外代理实测，6 个样本平均）。外推串行总时长 ~4.5 小时，在 GH Actions 6 小时 timeout 内；加 4-8 并发可压到 ~45 分钟。
  • 免费配额够用：预期每月 ~260 分钟，GH Free private repo 2000 min/月留有充分余量。

遗留风险

  • AKShare 库无 SLA，某周接口换了 / 限频炸了下周再补即可，数据延期一周对朋友圈场景无影响。GH Actions 失败默认发邮件给 owner，可观察。
  • 首次种数据必须本机手动一次：跑 snapshot build --all + gh release create data-snapshot ...。Actions 第一跑要能拉到有效 baseline。
  • 跨年 hot 滚动（2026 → 2027）需要本人 12/31 → 1/1 手动跑一次 snapshot roll-year；Actions 不感知跨年。
  • 实施时要给 pull_market 加 ThreadPoolExecutor 并发（4-8 worker），否则单跑 4.5 小时虽在 timeout 内但浪费配额。
